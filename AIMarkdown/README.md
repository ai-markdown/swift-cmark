# AI Markdown CMark

This branch provides the C parser behavior used by AI Markdown: lossless footnotes and references, highlight and definition-list syntax, math parsing, Web-compatible inline rules, source metadata for code and soft breaks, Web mdast list and list-item spread derived from a block-parser ledger, and Web mdast positions derived from parser events. Custom parser options retain their opt-in behavior.

`CMARK_OPT_WEB_TABLES` preserves actual scanned body cells, including pipe-only rows, and recognizes even/odd backslash escapes before dividers. It does not pad or truncate the raw AST to header width. Rendering consumers must normalize width where required; the ordinary GFM path retains its existing behavior. `web_table_test` covers input feeding, physical line endings, containers, opt-in isolation, and sparse-row storage. Paragraph-to-table conversion transfers the original physical line records before discarding the paragraph buffer; header and body cells record their actual inline-content anchors independently of their pipe-inclusive cell ranges. `web_table_prefix_test` checks 288 pinned Web inputs in root, quote, list and footnote containers.

Math flow values distinguish an enclosing container ending before ordinary flow from EOF, an explicit fence, or a new list/block-quote prefix. Only the former excludes an additional boundary line ending; internal blank lines, trailing spaces, and raw source ranges remain intact. `api_test` covers the boundary matrix with LF, CRLF and CR, both whole-input and byte-at-a-time feeds. A final prefix-only continuation without a physical EOL does not append its synthetic LF to math content; blank lines inside footnote math retain their real whitespace. Quoted EOF exits exclude the final physical quote line ending; a final container-only prefix without an EOL is distinguished from indentation consumed by the math fence. The 585 raw Web controls check value, native endpoints and published Web flow-event endpoints independently, including LF/CRLF/CR and byte feeds. Math openers and actual closing/container/EOF flow exits publish opt-in Web metadata independently of value compilation.

`CMARK_OPT_LIST_SPREAD_METADATA` records, per physical line, the containers that continue, open, and close, the leaf block that consumed the line, and whether an actual line ending was present. After parsing, `src/list_spread.c` expands that ledger into the document events read by `mdast-util-from-markdown`'s `prepareList`, applies the container-exit reordering of `micromark-util-subtokenize`, and derives the two independent `spread` values. `cmark_node_get_list_spread` returns 0 when no value was captured: for legacy footnote definitions without the lossless option that close on whitespace-only or CR-only blank lines, re-entrant feeding, or lists whose derived items differ from the parsed items. Rendering and `tight` are unchanged.

`CMARK_OPT_WEB_POSITIONS` records Web mdast positions next to the existing source positions, which stay unchanged. `cmark_node_get_web_position` returns 1-based lines and byte columns with an exclusive end, and a mask of the captured ends; callers must not substitute values for missing ends.

- Lists, list items, block quotes and footnote definitions use the same ledger: line endings start at the physical end of their line, list item prefixes end after the whitespace `listItemPrefix` includes, and container exits are placed where micromark's `document` tokenizer exits them before the `micromark-util-subtokenize` move and `prepareList`'s `listItem.end` are applied.
- Definition lists and descriptions record opaque document exits so an enclosing quote cannot move across their final line ending. Definition resolution records the exact boundaries of relocated lazy terms and merged descriptions; three or more adjacent merged segments preserve the pinned resolver's published second-segment end, even when later children extend beyond it; terms retain their original physical inline-content rows when split from paragraphs. Their presence no longer invalidates unrelated list spread or source events. A recognized document definition marker ends an unmatched container's lazy continuation even when it cannot bind an external term. Empty EOF descriptions use the current term-flow segment start after adjacent lists have merged. A partially consumed tab records the exact number of virtual spaces it emitted; a split term retains that physical anchor so virtual padding does not add source bytes.
- Fenced and indented code and HTML blocks end at their closing line, at the line ending before a lazy line, after the line ending before a new container or a final prefix-only line, at the end of input, or, for indented code, after the last line indented by four or more columns. Indented code and HTML blocks start before their indentation.
- ATX/setext headings and thematic breaks end at the physical end of their last line. Ordinary paragraphs retain actual first/last content-row anchors; a definition split that detached an EOL retains that physical EOL in the paragraph event. Task callback paragraphs keep their separate callback evidence, and existing table-prefix paragraph events are not overwritten.
- Inline nodes record the inline-subject span of the actual token: text excludes trailing line-suffix whitespace, soft breaks are their line ending, hard breaks cover the trailing spaces or backslash plus the line ending, emphasis covers the delimiters it used, and links and images span from the opening bracket. Spans are mapped through the physical start of each paragraph or heading content line, so continuation lines inside containers use their own start.
- Table rows start at their first non-whitespace character and end at the physical line end; each cell starts at its leading pipe or the row start and ends where the next scanned cell starts. `cmark_node_get_web_table_cells` returns the scanned cell count before cells were dropped or added to match the header.

Nothing is captured when the ledger is unsupported (as for list spread), when legacy non-lossless footnote blank prefixes make the flow differ, for legacy rows whose cell scan treats `\\|` as an escaped pipe (the Web table option removes this ambiguity), for table inline nodes without a captured physical content row, or where no physical event determines an endpoint.

Strikethrough records each actual delimiter-run subject span, including unmatched one/two-marker text. A resolved delete node retains its original opener/closer span through the type rewrite, so multiline and container positions use the physical content rows. This metadata is opt-in and does not change legacy native ranges or literal parsing; `web_tilde_positions_test` checks 252 actual Web inputs.

Web literal autolinks retain matched Link/Text subject spans for physical-row mapping. Hyphen and period are scan stops; underscore remains owned by the builtin attention parser and does not gain literal-token position evidence. `web_autolink_closeout_test` checks 277 actual Web inputs and opt-in isolation.

With definition-list syntax enabled, multiline inline HTML compiles the actual matched token's physical line endings and at most three virtual columns of linePrefix. Partially consumed tabs retain virtual spaces; a tab after that limit stays literal. This preserves the legacy profile's literal and source ranges, and keeps custom source coordinates independent of compiled value length. `web_inline_html_closeout_test` checks 365 actual Web raw/HAST inputs, including the original 34 multiline-tag math-boundary prefixes, whole/byte feeds and tracking parity. Corrected literal values do not imply continuous author-byte provenance or recovered HAST positions.

The upstream baseline is `08ddb528923cc1a6527e02b7a1aee9e516ca749a`. This repository retains upstream names; `ai-markdown-parser-swift` owns symbol isolation and Swift Package distribution. Maintain parser changes here rather than reapplying the same patches in the integration repository.

Original implementation provenance, patch paths, and checksums are recorded in `provenance.json`. Third-party licenses are bundled in `ThirdPartyLicenses`; upstream license files remain unchanged. The source paths in the provenance record refer to the pinned `ai-markdown-swift` source repository, not to files in this fork.

The lossless footnote profile combined with `WEB_CODE_SYNTAX` treats every physical blank line as a non-consuming continuation; the flag-off legacy profile retains its original blank-prefix consumption. This retains whitespace for nested flows and makes previously unsupported whitespace/CR footnote ledger endpoints comparable. `WEB_CODE_SYNTAX` also retains the document flow interruption state of indented code: a still-open flow restricts an interrupting ordered marker to `1`, while a code chunk opened by exiting an unmatched container closes at that physical EOL. Definition marker interruption respects item/footnote scopes, preserving lazy continuation inside nested lists. `web_list_boundaries_test` freezes 1639 actual Web inputs; the existing 5791-input legacy-table spread census has zero missing fields, shape differences or captured spread mismatches. These opt-in changes do not alter the upstream parser profile.

Definition resolution records a detached physical line ending before moving its content rows. Actual trailing-space and odd-backslash hard breaks retain their token start through the line ending; ordinary detached endings become `SoftBreak` nodes with their original physical ending, allowing later remark-breaks emulation to distinguish generated positionless nodes from actual hard-break tokens. `web_definition_breaks_test` checks 54 actual Web raw trees. Indented code opened inside a new document container does not inherit the exited container's one-line flow boundary.

An indented definition marker clears the prior blank-line spread flag when its continuation attempts indentation; an initially blank description retains the flag on its distinct early-exit branch. Both states are checked independently against actual Web description spread.

Block opening caches the original flow-interruption facts before adding children: finalizing a reference-only paragraph can free the prior current node, so later prefix checks must not dereference it. The legacy autolink protocol lookbehind keeps its negative index in `ptrdiff_t` arithmetic, avoiding unsigned pointer-offset overflow without changing the selected byte. Strict AddressSanitizer/UndefinedBehaviorSanitizer checks cover both paths.

`CMARK_OPT_WEB_HTML_BLOCKS` explicitly enables Web HTML declaration starts, including lowercase ASCII declaration names. Type-seven HTML flow on a lazy line remains in its actual existing document container until the next physical prefix decides its exit; it does not absorb following out-of-container text. Active flow interruption is respected through newly opened prefixes. `web_html_blocks_test` checks 627 actual raw Web inputs, including both original incremental failure traces. This option changes parsing only when enabled, independently of source-position tracking.
