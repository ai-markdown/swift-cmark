# AI Markdown CMark

This branch provides the C parser behavior used by AI Markdown: lossless footnotes and references, highlight and definition-list syntax, math parsing, Web-compatible inline rules, source metadata for code and soft breaks, Web mdast list and list-item spread derived from a block-parser ledger, and Web mdast positions derived from parser events. Custom parser options retain their opt-in behavior.

`CMARK_OPT_WEB_TABLES` preserves actual scanned body cells, including pipe-only rows, and recognizes even/odd backslash escapes before dividers. It does not pad or truncate the raw AST to header width. Rendering consumers must normalize width where required; the ordinary GFM path retains its existing behavior. `web_table_test` covers input feeding, physical line endings, containers, opt-in isolation, and sparse-row storage. Paragraph-to-table conversion transfers the original physical line records before discarding the paragraph buffer; header and body cells record their actual inline-content anchors independently of their pipe-inclusive cell ranges. `web_table_prefix_test` checks 288 pinned Web inputs in root, quote, list and footnote containers.

Math flow values distinguish an enclosing container ending before ordinary flow from EOF, an explicit fence, or a new list/block-quote prefix. Only the former excludes an additional boundary line ending; internal blank lines, trailing spaces, and raw source ranges remain intact. `api_test` covers the boundary matrix with LF, CRLF and CR, both whole-input and byte-at-a-time feeds. A final prefix-only continuation without a physical EOL does not append its synthetic LF to math content; blank lines inside footnote math retain their real whitespace. Quoted EOF exits exclude the final physical quote line ending; a final container-only prefix without an EOL is distinguished from indentation consumed by the math fence. The 585 raw Web controls check value and both source endpoints independently, including LF/CRLF/CR and byte feeds.

`CMARK_OPT_LIST_SPREAD_METADATA` records, per physical line, the containers that continue, open, and close, the leaf block that consumed the line, and whether an actual line ending was present. After parsing, `src/list_spread.c` expands that ledger into the document events read by `mdast-util-from-markdown`'s `prepareList`, applies the container-exit reordering of `micromark-util-subtokenize`, and derives the two independent `spread` values. `cmark_node_get_list_spread` returns 0 when no value was captured: for footnote definitions that this parser closes on whitespace-only or CR-only blank lines, re-entrant feeding, or lists whose derived items differ from the parsed items. Rendering and `tight` are unchanged.

`CMARK_OPT_WEB_POSITIONS` records Web mdast positions next to the existing source positions, which stay unchanged. `cmark_node_get_web_position` returns 1-based lines and byte columns with an exclusive end, and a mask of the captured ends; callers must not substitute values for missing ends.

- Lists, list items, block quotes and footnote definitions use the same ledger: line endings start at the physical end of their line, list item prefixes end after the whitespace `listItemPrefix` includes, and container exits are placed where micromark's `document` tokenizer exits them before the `micromark-util-subtokenize` move and `prepareList`'s `listItem.end` are applied.
- Definition lists and descriptions record opaque document exits so an enclosing quote cannot move across their final line ending. Definition resolution records the exact boundaries of relocated lazy terms and merged descriptions; three or more adjacent merged segments preserve the pinned resolver's published second-segment end, even when later children extend beyond it; terms retain their original physical inline-content rows when split from paragraphs. Their presence no longer invalidates unrelated list spread or source events. A recognized document definition marker ends an unmatched container's lazy continuation even when it cannot bind an external term. Empty EOF descriptions use the current term-flow segment start after adjacent lists have merged. A partially consumed tab that adds virtual spaces can still leave a term text position unknown.
- Fenced and indented code and HTML blocks end at their closing line, at the line ending before a lazy line, after the line ending before a new container or a final prefix-only line, at the end of input, or, for indented code, after the last line indented by four or more columns. Indented code and HTML blocks start before their indentation.
- ATX and setext headings end at the physical end of their last line.
- Inline nodes record the inline-subject span of the actual token: text excludes trailing line-suffix whitespace, soft breaks are their line ending, hard breaks cover the trailing spaces or backslash plus the line ending, emphasis covers the delimiters it used, and links and images span from the opening bracket. Spans are mapped through the physical start of each paragraph or heading content line, so continuation lines inside containers use their own start.
- Table rows start at their first non-whitespace character and end at the physical line end; each cell starts at its leading pipe or the row start and ends where the next scanned cell starts. `cmark_node_get_web_table_cells` returns the scanned cell count before cells were dropped or added to match the header.

Nothing is captured when the ledger is unsupported (as for list spread), when whitespace-only lines inside a footnote definition's code or HTML make the flow differ, for legacy rows whose cell scan treats `\\|` as an escaped pipe (the Web table option removes this ambiguity), for table inline nodes without a captured physical content row, or where a partially consumed tab leaves a point unknown.

Web literal autolinks retain matched Link/Text subject spans for physical-row mapping. Hyphen and period are scan stops; underscore remains owned by the builtin attention parser and does not gain literal-token position evidence. `web_autolink_closeout_test` checks 277 actual Web inputs and opt-in isolation.

With definition-list syntax enabled, multiline inline HTML compiles the actual matched token's physical line endings and at most three virtual columns of linePrefix. Partially consumed tabs retain virtual spaces; a tab after that limit stays literal. This preserves the legacy profile's literal and source ranges, and keeps custom source coordinates independent of compiled value length. `web_inline_html_closeout_test` checks 365 actual Web raw/HAST inputs, including the original 34 multiline-tag math-boundary prefixes, whole/byte feeds and tracking parity. Corrected literal values do not imply continuous author-byte provenance or recovered HAST positions.
